# User Preferences
- Co-locates Python scripts (e.g. `media-bridge.py`, `browser-mcp.py`) directly in the browser extension project directory alongside JS/CSS files, keeping the full stack in one tree rather than separating Python and extension code. Confidence: 0.75
- Chrome's "Load unpacked" rejects any directory starting with `_` (including Python's `__pycache__`), so when Python scripts run alongside extension files, `__pycache__` must be prevented or cleaned — the user prefers investigating permanent fixes (`.gitignore`, Python source-level config) over repeated manual deletion. Confidence: 0.65
- Develops on Windows with Chrome's unpacked-extension loader, which enforces strict directory naming constraints not present on all platforms. Confidence: 0.75
- Prefers compact, space-efficient UI layouts — single-line tool-trace rows with a dot status indicator and tool name/label, rather than chunky multi-section cards. Explicitly noted "it uses less space." Confidence: 0.85
- Does not tolerate `[object Object]` in rendered output — non-string payloads (e.g. tool input/args as objects) are expected to be properly serialized via JSON.stringify or structurally rendered, never left as raw object coercion. Confidence: 0.8
- Groups scattered execution traces (terminal, `_thinking`, `message.*`) into a single consolidated **Actions ▾** dropdown rather than letting them spill as individual rows — collapsed state shows `Actions · N` with a 2-item preview, expanded shows each step as a compact one-liner with dot status + inline detail-on-expand. Confidence: 0.9
- Demands desktop parity: the extension's action-dropdown UX (open state, item formatting, collapse behavior) should mirror what the desktop client displays, not diverge into a custom layout. Referenced via "the one shown in the desktop when action dropdown opens." Confidence: 0.85
- Prefers model/provider-lock mismatches (e.g. `require_model_lock` runtime mismatches surfaced by a gateway) to be **non-blocking**: shown as a muted info toast or tucked into the model picker at most, never as an obstructing red error banner over the chat. The user expects these to be server-side config issues and wants them de-emphasized in-extension rather than debugged client-side. Confidence: 0.85
- Historical/backfilled tool traces must render with the same fidelity as live-streamed ones — past terminal commands should display their actual command text and correct status (done/running/error), not as blank orange "running" placeholders with no command string. The user explicitly contrasts live traces (which show the command) against stale history loads (which don't). Confidence: 0.9
- Status indicators must be inferred from actual output/data presence rather than trusted from stale persisted status fields — a completed tool call with output should show as done, not remain stuck indefinitely on "running"; only genuinely incomplete calls should show running. Confidence: 0.85
- The extension must persist and reload session history across panel-openings — tool traces from before the panel was opened should be loaded from the gateway/backfill, not only events streamed during the current session. Confidence: 0.9
- For `<input type=file>` automation, expects the browser-protocol path (CDP `DOM.setFileInputFiles` / Playwright `setInputFiles` / Puppeteer `uploadFile`) over page-JS workarounds (DataTransfer/FileList assignment), because browsers hard-block script assignment to file inputs for security. Confidence: 0.85
- Instructs coding agents to consult all relevant official documentation (e.g., CDP protocol docs) before implementing a fix, not just codebase search. Confidence: 0.8
- Expects file-upload fixes to be verified against concrete real targets including wrapped inputs (e.g., `.dropify-wrapper` containing `input#entry_sheet_entry_values_attributes_16_filename`) rather than just generic inputs. Confidence: 0.75
- Requires composer input to stay enabled while a response is streaming so follow-up messages can be sent without waiting — blocking typing during generation prevents queue/steer usage. Confidence: 0.9
- Expects any message typed while a run is processing to implicitly operate as steer, with the send button swapping from arrow to steering-wheel icon (steer-ready) and falling back to Stop (square) when empty to make the mid-stream affordance explicit. Confidence: 0.85
- Prefers shell-style prompt history recall via Up/Down arrows — Up at caret start cycles backward through previous sent user messages, Down at caret end moves forward and restores the unfinished draft — with boundary-aware triggering so normal cursor movement inside multi-line text is preserved. Confidence: 0.85
